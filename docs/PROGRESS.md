## 第 2 批 · 引擎正确性（P2）

- **006 · P2 · 修分词丢弃连字符** — `GPT-4` 被切成 `gpt`，搜「gpt-4」永不命中。正则改为保留连字符的 `[a-z][a-z0-9+#.]*(?:-[a-z0-9.]+)*`。验证：单测断言 `gpt-4` 整体成词。
- **007 · P2 · 修短句被误判为待办** — 旧规则给「少于 45 字」无条件 +0.7，导致 38 字的观点被判成待办；且「做/约/买」这类单字出现在任意位置都算信号。改为：短句不加分；单字动词只在句首算信号；明确时间只在「已经像待办」时才加强。验证：14 条真实语料回归表全部通过。
- **008 · P2 · 分类打分可观测** — 新增 `Engine.classifyScore()`，把三类得分暴露出来，单测失败时能直接看到是哪条规则带偏了。
- **009 · P2 · 分词补二元组兜底** — 词典只有几百词，短句里一旦没有词典词就被整句丢掉：「明天下午三点前把 Q4 路线图发给张总…」旧实现只抽出 `q4` 一个词，检索与关联全废。改为词典最大匹配 + 未登录片段用字符二元组滑动兜底。验证：同句抽出 18 个词。
- **010 · P2 · 过滤虚词二元组** — 二元组会产出「的投」「图不」「要只」这类跨词碎片，既污染索引又让无关记录因共享碎片而显得相关。含虚词单字的二元组不入索引（词典成词不受影响）。验证：单测断言 `的投` 不出现。
- **011 · P2 · IDF 平滑** — 经典 `log(N/df)` 在只有两条记录时会把「两条都含有的词」权重压成 0，恰好抹掉了「它们讲同一件事」这个最强信号。改为 `log(1 + N/(df+0.5))`，恒为正。验证：两条同主题短文相似度从 0 升到 0.27。
- **012 · P2 · 索引缓存签名碰撞** — 旧签名是「条数 | 最后更新时间 | 首条 id」，导入一批条数与时间戳都相同的新数据时会复用旧索引。改为对全部 `id + updatedAt` 做 FNV-1a 累积哈希。验证：单测「条数相同内容全换」场景通过。
- **013 · P2 · 关联打分改「余弦 + 包含度」** — 纯余弦会被长度差异惩罚，两条 30 字的相关笔记相似度掉到阈值以下，导致「相关内容」长期为空。新增包含度（短文本被覆盖的比例，按 TF-IDF 权重加权，再用共享词数打折）。验证：4 组判定表 4/4 正确，无关对仍为 0。
- **014 · P2 · 标签抽取与索引分词分离** — 标签要"像词"，索引要"覆盖全"。新增 `tokenizeWords()` 只取词典成词供标签使用，索引仍走二元组；二字词共享一个字视为同一处文字的碎片并去重。验证：单测「标签不含天下」通过。

## 第 4 批 · 数据安全（P1）

- **016 · P1 · 删除改为软删除 + 回收站** — 本地应用没有服务端兜底，误删就是永久丢失。`Store.remove()` 改为移入回收站（带 `deletedAt`），新增 `trash / restore / purge / emptyTrash / trimTrash`；保留 30 天或最多 80 条。验证：单测覆盖「删除→回收站→恢复→字段完整」全链路。
- **017 · P1 · 撤销栈 + Ctrl+Z** — 每次增删改前把记录集快照进内存栈（上限 20 步，不落盘以免二次占用配额）。界面加 `Ctrl/⌘+Z`，并刻意跳过输入框内的按键——否则打字时按撤销会误删记录。验证：单测「撤销删除」+ e2e「点完勾选按 Ctrl+Z 状态翻回来」。
- **018 · P1 · 导入按内容指纹去重** — 同一份备份导入两次会把记录翻倍。新增 FNV-1a 指纹（类型 + 归一化正文），导入时跳过已存在的指纹，并区分「重复」与「无效」两类跳过。验证：单测「重复导入 added=0 / duplicated=1」。
- **019 · P1 · 配额写满时的自救与告知** — 写库失败曾经只在控制台打日志。现在：先清回收站里较旧的条目再重试一次，仍失败才把可操作提示（导出 / 清理）弹给用户。验证：单测用 400 字节配额的假 localStorage 触发失败并断言提示文案。
- **020 · P1 · 数据完整性修复** — `Store.repair()` 在载入时体检：剔除空正文、去重 id、收敛非法类型/优先级、截断超长正文、剔除指向不存在记录的悬空关联。验证：单测构造 4 条脏数据，修复后条数、id 唯一性、类型收敛均符合预期。
- **021 · P1 · schema 版本与迁移入口** — 新增 `info_butler_meta_v1` 存 `schemaVersion`，`migrate()` 从 v1 升到 v2 时补齐指纹等新字段。老 localStorage 与老备份都能直接用。验证：单测断言 meta 写入。
- **022 · P1 · 导出 Markdown** — 按类型分组，保留完成状态、截止日、重点标记与标签，可直接粘进任何笔记软件。验证：单测断言分组标题与状态文案。
- **023 · P1 · 导出 CSV** — 带 UTF-8 BOM（Excel 打开不乱码），正确转义逗号与引号。验证：单测断言 BOM 首字节与 `""引号""` 转义。
- **024 · P1 · Toast 支持动作按钮** — 原来的提示只能看不能点。现在可挂一个动作（如「撤销」），带动作时停留 6 秒而不是 2.4 秒。验证：e2e 删除后点提示里的「撤销」能恢复记录。
- **025 · P1 · 设置页回收站面板** — 列出被删记录（标题、类型、删除于几天前），支持单条恢复 / 彻底删除 / 清空。验证：e2e 打开设置页断言回收站区域有内容。
- **026 · P1 · 存储用量可视化** — 设置页显示「已用 X KB / 约 5 MB（N%）」进度条，60% 转黄、84% 转红；超过 4.2MB 时主动提示（同一条提示 5 分钟内只弹一次，否则每次保存都弹）。验证：e2e 断言用量文案出现。

- **034 · P4 · 命令面板** — `Ctrl/⌘+K` 唤起，命令与记录统一搜索：输入「浅色」能切主题，输入「路线图」能直接跳到那条笔记。支持 ↑↓ 选择、Enter 执行、Esc 关闭、点击执行。验证：e2e 两项（搜到记录 / 切主题生效）。

## 第 7 批 · 性能（P3）

- **037 · P3 · 性能基准工具** — 新增 `tools/bench.js`：真实浏览器里灌 N 条记录，测建索引 / 关联 / 首屏渲染 / 检索 / 筛选 / 总结的耗时，超过 300ms 标「偏慢」。没有基线就没法判断优化有没有用。验证：`npm run bench` 输出表格。
- **038 · P3 · 关联从 O(n²) 改为倒排召回** — 2000 条记录 = 200 万对两两比较，实测 **4313ms**；而这段代码在每次启动都会跑，等于开屏卡 4 秒。改为先建倒排索引（只收权重 ≥0.08 的词，单个词倒排表截断到 80），用「共享 ≥2 个有区分度的词」召回候选，再只对候选集精算（每条最多 40 个）。验证：同样 2000 条降到 **203ms**，21 倍；关联判定表 4/4 仍正确。
- **039 · P3 · 列表分批渲染** — 2000 条记录会一次性生成 666 个卡片 DOM（当前筛选下），首屏渲染 44.5ms 且滚动明显发涩。改为每批 60 条 + 「继续加载」+ `IntersectionObserver` 滚动到底自动补；换筛选/换关键词时重置回第一批。验证：DOM 卡片 666 → **60**，首屏渲染 44.5ms → **2.1ms**；e2e「大列表分批渲染」通过。
- **040 · P3 · 调试接口** — 暴露 `window.__infoButler`（state / renderStream / switchView / openPalette / applyTheme），供压测与自动化验证使用；只给幂等能力，不留"直接改数据"的后门。
- **041 · P9 · e2e 扩到 19 项** — 新增「大列表分批渲染」。验证：19/19 通过。

## 第 8 批 · 无障碍与标签维护（P5 / P4）

- **042 · P5 · 无障碍基础** — 加「跳到内容列表」跳转链接（键盘用户不必 Tab 过整个侧边栏）、`:focus-visible` 焦点框（鼠标点击不出现）、`prefers-reduced-motion`（系统开了减少动效就关掉动画）、`.sr-only` 工具类；补齐 `nav` / `searchbox` / `list` / `dialog` / `status` 等语义与 `aria-label`。验证：e2e「关键控件具备可读的无障碍名称」「存在跳到内容的跳转链接」。
- **043 · P5 · 焦点陷阱与归还** — Tab 键在弹层内循环，关闭后焦点回到触发元素。用 MutationObserver 监听各层 `hidden` 变化来接管焦点，这样不必改动十几处 `el.hidden = true` 的调用点。验证：e2e 连按 20 次 Tab 焦点不逃逸，Esc 关闭后焦点回到卡片标题。
- **044 · P5 · 卡片标题改成真按钮** — 这条是 e2e 的 Tab 测试逼出来的：标题原本是 `<h3>`，不可聚焦、不响应 Enter，**键盘用户根本打不开任何一条记录**，只能去点右下角不起眼的「详情」。改成 `<button>` 后 Enter 即可进入详情。验证：e2e 焦点归还断言命中 `.card-title`。
- **045 · P4 · 标签重命名 / 合并 / 删除** — 标签靠自动抽取，难免出现「产品」「产品思考」这类近义或错字，以前没有任何修正手段。新增 `Store.renameTag / deleteTag`：重命名为已存在的标签即合并，且同一条记录上的重复标签会去重；删除只摘标签不删记录。设置页新增「标签管理」面板。验证：单测 4 项（重命名、合并去重、空操作、只摘标签）。
- **046 · P9 · 测试规模** — 单测 47 项、e2e 22 项。验证：全绿。

## 第 10 批 · 记录间移动与重复检测（P4 / P2）

- **054 · P4 · 详情里前后导航** — 看完一条想看下一条，以前要关掉抽屉再点。新增「上一条 / 下一条」按钮 + `←` `→` 快捷键，并显示当前位置（`3 / 42`）。邻居按**当前列表的可见顺序**取，所以在筛选或搜索状态下翻页也符合预期。验证：e2e「详情里可用 ← → 在记录间移动」。
- **055 · P2 · 近重复检测** — 同一件事记两遍是最常见的数据质量问题。新增 `Engine.findSimilar()`：只看正文（标签相同、类型相同都不算理由），用「余弦 0.5 + 包含度 0.5」打分，阈值 0.82。保存新记录后立刻检查，命中就提示「与「X」高度相似」并给出「查看」按钮——刚记完是最该提醒的时刻，事后翻列表才发现就晚了。验证：单测 3 项（命中重复 / 不因标签相同误报 / 排除自身）+ e2e 一项。
- **056 · P2 · 索引签名再加固** — 单测暴露出一个边界：id 与时间戳都相同、只有正文不同时，签名仍然碰撞。把正文与标题长度也纳入哈希。这是防御性改动（正常写入路径会更新 `updatedAt`），但成本近乎为零。

## 第 12 批 · 时间维度检索（P2 / P4）

- **059 · P2 · 查询里的时间表达式** — 「上周关于产品的想法」这类查询，时间词以前会被当成普通词参与 TF-IDF，等于永远搜不到。新增 `Engine.parseTimeRange()`：识别 今天/昨天/前天/本周/上周/本月/上个月/今年/去年/最近 N 天·周·月/N 天前，把时间词剥出来变成**硬过滤**，剩下的部分继续走关键词检索；剥完残留的「的/期间/内」等连接词一并清掉，否则会变成噪声关键词。验证：`tests/time.test.js` 11 项，覆盖范围边界（本周从周一算起）、`cleaned` 残留清洗、时间+关键词组合、范围内无结果返回空而不是全量。
- **060 · P2 · 时间过滤下不再叠「越新越靠前」** — 单测逼出来的：「本周产品」会把同时间段的健身记录也搜出来，因为 `intent.recent` 给所有新记录加了 1.55 分，越过 0.35 的入选线。时间既然已经是硬过滤，这个加分就是纯噪声，识别出时间范围时直接删掉 `intent.recent`。验证：`search 时间 + 关键词同时生效` 从 2 条收敛到 1 条。
- **061 · P4 · 时间条件回显为可取消的 chip** — 用户不知道「今天」被当成条件吃掉了，会以为搜不到东西。记录流副标题与筛选条都显式回显「时间：今天」，chip 用虚线边框区别于用户直接输入的关键词；点一下只摘掉时间词、保留剩余关键词（`cleaned`），而不是整串清空。验证：e2e「搜索里的时间词会变成可取消的筛选条件」。

## 第 13 批 · 到期提醒（P4 / P2）

- **062 · P2 · 待办到期分桶** — `dueDate` 以前只是卡片上的一个字符串：逾期项在「最近创建」排序里天然沉底，等于没有任何提醒。新增 `Engine.dueBuckets(notes, now)`，把未完成待办分成 逾期 / 今天 / 未来 7 天 三桶，桶内按截止日升序、同日按优先级降序。`now` 可注入，测试不会因为跨天而抖动。验证：`tests/due.test.js` 5 项（含已完成/非待办不计入、排序、空数据）。
- **063 · P4 · 首页提醒条** — 记录流顶部新增一条提醒：有逾期就红底显示「有 N 项已逾期，最早一项「X」拖了 N 天」，只有今天到期就黄底，本周内到期则用中性色。点「只看到期 / 只看今天 / 只看本周」直接把列表筛到这些项，筛选条上出现可取消的 chip；点 × 本次会话不再打扰。验证：e2e「首页提醒条把快到期的待办捞到顶上」+「待办全部完成后提醒条自动消失」。
- **064 · P4 · 提醒条的边界处理** — 清空筛选、空态判断都要认识 `dueFilter`，否则「只看今天」之后点「清除筛选条件」会回到一个既非空也非全量的怪状态。验证：e2e 全绿 + 手动走查三条路径。

## 第 14 批 · PDF 导入（P8）

- **065 · P8 · 零依赖 PDF 文本提取** — 资料收集里 PDF 是最高频格式，之前完全不支持。新增 `extractPdf()`：latin1 结构扫描建对象表 → 展开 ObjStm（现代 PDF 把页面字典压进对象流，不展开就一个页面都找不到）→ 走 `/Pages` 树保证页序 → 解 FlateDecode → 解析 `Tj / TJ / ' / "` 与 `Td / TD / T*` 还原换行。中文 PDF 靠 `ToUnicode` CMap（`bfchar` + `bfrange`，含区间递增）还原汉字；拿不到映射时明确报「无法还原」而不是灌乱码。验证：`tests/pdf.test.js` 9 项，PDF 全部由 `tests/fixtures.js` 现场生成（不往仓库塞二进制样本）。
- **066 · P8 · 扫描件与加密件给可操作提示** — 扫描件没有文字层，返回空文本会让用户以为「导入成功了但内容没了」。现在分别报「多半是扫描件，需要 OCR」与「PDF 已加密，请另存为不加密版本」。验证：单测两项断言错误文案。
- **067 · P8 · 导入入口接入 PDF** — 文件选择框 `accept` 加 `.pdf`，设置页说明文案补上 PDF 与 OCR 限制；扩展名写错时按内容嗅探（`%PDF` 头）走 PDF 分支。验证：e2e「可以导入 PDF 并提取出文字」——真实走一遍 FileReader → DocImport → Store → 列表渲染。

## 第 15 批 · 批量操作与自绘对话框（P4）

- **068 · P4 · 批量改走单次事务** — 逐条 `update()` 会做 N 次快照 + N 次整库 `JSON.stringify`，选 200 条就是 200 次全量序列化。新增 `Store.batchUpdate(ids, patch)`：一次快照、一次落盘，`patch` 可传对象也可传函数（按条计算）。验证：单测用计数器断言 5 条只写库 1 次。
- **069 · P1 · 批量删除必须与单条删除同语义** — 第一版只给记录打 `deletedAt`，结果记录既没离开活跃列表、也没进回收站，成了"看着删了、回收站里却没有"的幽灵数据。**这是单测抓出来的**：改为原地 splice 移出 + 剔除双向关联 + 写入回收站，与 `remove()` 完全一致。验证：单测「移入回收站而不是物理删除」「删除后可恢复」。
- **070 · P4 · 批量操作 UI** — 记录流头部新增「批量」开关；进入后卡片左侧出现选择框，点卡片任意位置都是勾选（避免误开详情）；底部出现操作条：标为想法/资料/待办、设为重点、加标签、删除，选中 0 项时按钮全部禁用。删除后 toast 带「撤销」。验证：e2e「批量选择后可以一次改类型」。
- **071 · P4 · 自绘输入对话框替换原生 prompt** — 原生 `prompt` 阻塞整页、样式无法控制、部分环境直接被拦截。新增 `askText()`：与整体视觉一致的弹层，支持标题/说明/提示文案、Enter 提交、Esc 关闭、焦点自动落到输入框并全选。标签重命名与批量加标签都改走它，代码里已无 `window.prompt`。验证：e2e「批量加标签走自绘对话框而不是原生 prompt」。
- **072 · P5 · 新弹层接入焦点与 Esc 体系** — `askModal` 加入 `LAYER_IDS`，复用已有的焦点陷阱与「关闭后焦点归还」；Esc 的关闭顺序也把它排在命令面板之前。验证：e2e 无障碍三项仍全绿。

## 第 16 批 · 修偶发失败（P5 / P9）

- **073 · P5 · 焦点陷阱在「弹层已开、内容未渲染」时会漏** — e2e 连跑四次会挂一次「Tab 焦点被困在弹层内」。根因不是测试不稳定，而是真实缺陷：抽屉刚打开、`#detailBox` 还没填内容时，层内一个可聚焦元素都没有，`trapTab` 直接 `return`，于是 Tab 把焦点推出了弹层——键盘用户会当场"掉出"对话框。改为：层内无可聚焦元素时拦住 Tab 并把焦点落在层本身（临时 `tabindex="-1"`）。验证：连跑 6 次 30/30。
- **074 · P5 · 关闭后焦点归还的兜底** — 触发元素若在弹层打开期间被列表重渲染掉，`focus()` 会静默失败，焦点落到 `<body>`。改为先判断 `document.body.contains`，失效时交还给「当前列表第一条的标题」或搜索框。验证：同上。
