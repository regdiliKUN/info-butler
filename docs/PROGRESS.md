## 第 2 批 · 引擎正确性（P2）

- **006 · P2 · 修分词丢弃连字符** — `GPT-4` 被切成 `gpt`，搜「gpt-4」永不命中。正则改为保留连字符的 `[a-z][a-z0-9+#.]*(?:-[a-z0-9.]+)*`。验证：单测断言 `gpt-4` 整体成词。
- **007 · P2 · 修短句被误判为待办** — 旧规则给「少于 45 字」无条件 +0.7，导致 38 字的观点被判成待办；且「做/约/买」这类单字出现在任意位置都算信号。改为：短句不加分；单字动词只在句首算信号；明确时间只在「已经像待办」时才加强。验证：14 条真实语料回归表全部通过。
- **008 · P2 · 分类打分可观测** — 新增 `Engine.classifyScore()`，把三类得分暴露出来，单测失败时能直接看到是哪条规则带偏了。
- **009 · P2 · 分词补二元组兜底** — 词典只有几百词，短句里一旦没有词典词就被整句丢掉：「明天下午三点前把 Q4 路线图发给张总…」旧实现只抽出 `q4` 一个词，检索与关联全废。改为词典最大匹配 + 未登录片段用字符二元组滑动兜底。验证：同句抽出 18 个词。
- **010 · P2 · 过滤虚词二元组** — 二元组会产出「的投」「图不」「要只」这类跨词碎片，既污染索引又让无关记录因共享碎片而显得相关。含虚词单字的二元组不入索引（词典成词不受影响）。验证：单测断言 `的投` 不出现。
- **011 · P2 · IDF 平滑** — 经典 `log(N/df)` 在只有两条记录时会把「两条都含有的词」权重压成 0，恰好抹掉了「它们讲同一件事」这个最强信号。改为 `log(1 + N/(df+0.5))`，恒为正。验证：两条同主题短文相似度从 0 升到 0.27。
- **012 · P2 · 索引缓存签名碰撞** — 旧签名是「条数 | 最后更新时间 | 首条 id」，导入一批条数与时间戳都相同的新数据时会复用旧索引。改为对全部 `id + updatedAt` 做 FNV-1a 累积哈希。验证：单测「条数相同内容全换」场景通过。
- **013 · P2 · 关联打分改「余弦 + 包含度」** — 纯余弦会被长度差异惩罚，两条 30 字的相关笔记相似度掉到阈值以下，导致「相关内容」长期为空。新增包含度（短文本被覆盖的比例，按 TF-IDF 权重加权，再用共享词数打折）。验证：4 组判定表 4/4 正确，无关对仍为 0。
- **014 · P2 · 标签抽取与索引分词分离** — 标签要"像词"，索引要"覆盖全"。新增 `tokenizeWords()` 只取词典成词供标签使用，索引仍走二元组；二字词共享一个字视为同一处文字的碎片并去重。验证：单测「标签不含天下」通过。
