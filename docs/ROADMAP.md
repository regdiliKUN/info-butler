# 信息管家 · 优化路线图（1000 轮）

> 目标：把一个「能用的本地笔记应用」打磨成「敢长期托付个人信息的本地知识库」。
> 每一轮必须是**可验证的实际改动**（代码 / 测试 / 构建产物之一），不接受"看了看没改"。

## 约束

1. 保持**零运行时依赖**：纯静态、双击即用、断网可用。不引入框架、不引入 CDN。
2. 保持**本地优先**：任何联网能力必须可关闭，且默认关闭。
3. 每轮改动都要能通过 `npm test`；涉及界面的要过 `npm run test:e2e`。
4. 数据格式**向后兼容**：老备份能导入，老 localStorage 能自动迁移。

## 十个阶段

### P1 数据安全（1–100）
本地应用最致命的问题是"数据悄悄没了"。这一阶段全部围绕可靠性。

1. localStorage 分片存储，突破 5MB 单 key 上限
2. 写入前配额预检，失败时给出可操作提示（导出/清理/删旧）
3. 自动快照：最近 N 次变更留可回滚副本
4. 快照轮转与容量上限
5. 回收站（软删除）+ 恢复 + 彻底删除
6. 撤销栈（Ctrl+Z），覆盖增删改
7. 导入去重（内容指纹）
8. 导入前预览与冲突处理
9. 数据完整性校验与自动修复（悬空 related / 非法字段）
10. schema 版本号与迁移器
11. 多标签页同步（storage 事件 + 乐观锁）
12. 导出 Markdown / CSV / 纯文本
13. 导出包含配置与统计
14. 备份文件校验（导入前 dry-run）
15. 存储占用明细（按类型/时间）
16. 单条正文超限时的显式提示
17. 事务式批量写入（失败回滚）
18. 崩溃恢复（写入中途中断的脏数据识别）
19. 数据统计面板
20. 定期备份提醒

## 执行方式

- 每轮在 `docs/PROGRESS.md` 追加一行：轮次号 · 阶段 · 改了什么 · 怎么验证的。
- 每 10 轮跑一次全量测试 + e2e，通过后 git commit。
- 轮次编号连续，不跳号；发现的新问题进 `docs/BACKLOG.md`，不打断当前轮。
